Connect your local agent

No local agent is connected. Questions stay saved in the queue, but will not answer themselves.

  1. Use an already-running, local-only agent with the Sillage skill (skills/sillage/SKILL.md). Ask it to connect to this reader’s local relay and answer queued questions. Do not use a cloud-backed agent.
  2. For a stdio-capable local agent, start node src/local-agent.js from the Sillage checkout and attach its stdin/stdout, keeping stderr separate. Use Node directly: npm's normal script banner can pollute the JSONL stream. For a nondefault loopback port, use e.g. SILLAGE_URL=http://127.0.0.1:3211 node src/local-agent.js with the reader's port. Send {"type":"ready","worker":"my-local-agent"} only when ready to answer. The bridge prints requests as JSON lines; the agent must return answers. See docs/local-agent.md.
  3. The indicator becomes active only after connection; heartbeat loss makes it unavailable. Stop via the agent’s disconnect action or end the bridge’s input. In-flight work gets an explicit failure, never a fabricated answer.

Sillage cannot start a model or execute commands. This bridge is not AI. The separate npm run fake-agent command is a deterministic demo, not the active-agent path. Nothing here authorizes project edits, deletion, publication or merges.

One report, evolving over time

Import / new revision brings in a newer version of this same report, not a different report. Durable conversations and their original quotes, citations and source snapshots are preserved. Only safe matches are retained; changed or ambiguous passages are marked for review, never silently remapped.

Live updates · on this PC

Revisions imported here or through the local relay appear automatically in open readers. To observe edits on disk, explicitly connect the same Markdown file after importing it. Read-only permission lasts only in this tab; no paths are sent to the server.
